# Context audit

Argument: `$ARGUMENTS`

| Argument | Mode | Writes |
|---|---|---|
| empty, `deep`, `universal`, `project` (combinable) | **quick**: one-shot audit, at most 10 findings, user triages | what user approves |
| `auto` | **auto**: unattended, applies only the low-risk class, queues the rest | patch tools, capped |
| `inventory` | **inventory**: every file in the system reviewed through the ledger | the ledger and one report doc |

Audit the store, never a projection. `.agents/` and `.claude/` are generated by `project-materialize.py`, `agents-materialize.py` and `home-materialize.py`; `settings.json` and the hook scripts it wires are checked on disk. A projection that disagrees with the store is a finding: `python3 ~/.agent-context/global/scripts/project-materialize.py --check <repo>` reports that drift (exit 3). Layout: `get_doc("agents-layout.md")`.

The rubric for every mode:

1. A rule states a principle and its reason. Where a hook enforces a rule, the text points at the hook and does not restate it.
2. Each fact lives in one place; everything else points at it.
3. Always-loaded text holds only what every session needs; the rest loads on demand.
4. Operative text has no incident stories, quotes, dates or capitals for emphasis. History lives in archive docs.
5. Nothing contradicts the harness, another layer, or the current tree.
6. A memory holds current state. One that grows by appended incidents splits into a current-state memory and an archive doc.
7. A description states the trigger in 140 characters or fewer; `load_behavior` is explicit.

## Quick mode (default)

Scope words: `universal` (global entities and `~/.claude/` only), `project` (the current project only), neither (both). `deep` adds the last 5 transcripts in `~/.claude/projects/<encoded-cwd>/` as evidence: repeated reads, user corrections, rules the agent re-derived.

1. Reset the audit-nudge clock:
   ```bash
   mkdir -p ~/.local/state/agent-context/audit && touch ~/.local/state/agent-context/audit/last-$(pwd | sed 's|/|-|g')
   ```
2. Run the mechanical sweeps before reading anything by hand: `check_integrity(summary=True)` and `python3 ~/.agent-context/global/scripts/store-compact.py --json`. Do not re-derive what they return.
3. Read the open audit observations (`list_audit_observations(project, status="open")`); each is a finding candidate. Read the search misses too (`get_usage_report()`, field `search_misses`): a repeated miss is a row to add to `how-to.md` or a `keywords` entry for the entity that answers it.
4. Read the layers in scope: always-loaded instructions, docs (`list_entities("doc")`, then `get_doc` on the suspicious ones and the ones instructions point at), memory (`list_entities("memory", project, limit=0)`), skills, commands, hooks, and the disk `settings.json`. Verify a memory claim against source before calling it stale.
5. Findings, judged against the rubric: stale memory, dead docs, buried rules, duplication across layers, vague rules, missing automation (or prose re-teaching what a hook does), always-loaded bloat, conflicts, overlapping skills or commands, hook wiring gaps, index husks.
6. Present: a header (`Audited: universal + project (static). 4 findings.`), then per finding a title, the entity and the quote that proves it, the proposed change, and its effect. At most 10, ranked by effect; zero findings is one sentence.
7. Triage through `AskUserQuestion`, four findings per question: Apply, Skip, or Tell me how.
8. Applying: a change that moves memory content into a doc or instruction deletes the redundant memory in the same step. A finding from an observation resolves it (`resolve_audit_observation`). Edit the store record; the materializer updates disk.

Budget: about 20k tokens of reads static, 10-30k more for `deep`. Read transcripts with targeted greps.

## Auto mode

Runs headless, launched by the `context-audit-autorun` SessionStart hook with `AGENT_CONTEXT_AUTO_AUDIT_RUN=1` set (it stops the hook recursing; leave it set). The hook launches it only where `~/.local/state/agent-context/audit/auto-audit-enabled` exists; no machine has that marker (policy). Nobody is watching: when in doubt, queue.

1. **Reap and list:** `python3 ~/.agent-context/global/scripts/store-compact.py --apply --json`. It archives spent observations and handoffs and returns the `work` list across every scope, each item with the MCP call that fixes it. That list is the candidate set.
2. **Integrity:** `check_integrity()` once. `cold_always_loaded` and `stale_always_loaded` are the evidence for tiering: work those first. An empty `cold_always_loaded` means no evidence yet (check `enough_evidence`).
   A `broken_pointers` or `dangling_links` fix that applies the `suggest` target is low-risk only when the target exists on disk in the store; `suggest` comes from the daemon index, which can hold deleted entities. Otherwise queue it. Queue `duplicate_bodies`, `orphan_scopes`, `over_instruction_budget` and `unindexed:` load errors.
3. **Observations, worst then oldest:** `list_audit_observations(status="open")` for global and each project (`list_entities("project", limit=0)`), and `needs_reverify=True`.
4. **Drain first**, up to 10 re-verifications, outside the change cap:
   - condition gone: `resolve_audit_observation(id, status="resolved", resolution_note="obsolete on re-verification <date>: <why>")`;
   - still live: `update_audit_observation(id, note="re-verified <date>: still live at <file:symbol>")`, `severity="blocker"` if it stops work;
   - not checkable unattended: note what it needs and leave it open;
   - two records for one defect: fold the newer into the older (`recurred=True`) and resolve the newer as a duplicate.
5. **Apply only this class**, at most 20 changes, round-robin across scopes, patch tools only (`upsert_memory` with no body, `edit_body` on memory or doc, `upsert_doc(append=True)`):
   - trim a memory description over 140 characters, keeping its meaning;
   - correct a description verified wrong against source this run (description only);
   - tighten a husk memory with `edit_body` when its invariant stays;
   - tier a memory `always` to `lazy`, at most 5 per run, only when all hold: you read the full body this run; `memory_type` is `project`; the body is archival (never started, finished, or a resolved incident recorded elsewhere); it holds no standing invariant, gotcha or "do not" guard; it has no live thread (pending, next, blocked).
6. **Queue everything else** with `add_audit_observation` (severity `blocker` only when work stops, `high` when context is lost or corrupted). If it returns `possible_duplicate_of`, fold into that id. Always queue: server code, any deletion, instruction or structural changes, `lazy` to `always`, hook, script, settings or guardrail changes, full-body rewrites, dangling links, anything uncertain.
7. **Finalize, always:**
   ```bash
   python3 "$HOME/.agent-context/global/scripts/store-state.py" finish-audit
   LOG="$HOME/.local/state/agent-context/audit/context-auto-history.log"
   mkdir -p "$(dirname "$LOG")"
   printf '%s host=%s applied=%d queued=%d reverified=%d resolved=%d open_after=%d capped=%s note=%s\n' \
     "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$(hostname -s 2>/dev/null || echo '?')" \
     "$APPLIED_COUNT" "$QUEUED_COUNT" "$REVERIFIED_COUNT" "$RESOLVED_COUNT" \
     "$OPEN_AFTER" "$CAPPED" "$NOTE" >> "$LOG"
   ```
   Substitute the real counts. If `queued` exceeds `resolved` run after run, say so in `note`. The human digest renders itself in the inbox; preview it with `python3 ~/.agent-context/global/scripts/audit-digest.py --dry-run`. Do not commit; the daemon commits every store write.

End with a 2-3 line summary. Ask no questions.

## Inventory mode

Every file in the store and its installed harness copies, each reviewed at its depth against the rubric. Report-only: it writes the ledger and one report doc, and changes nothing else. The findings become a worklist the lead works in later chunks.

Run it on ls. Build and batch are server tasks (policy), so the ledger lives on the daemon host, and the reviewers read store files by path. Ledger: `$CONTEXT_INVENTORY_DIR`, default `~/.local/state/agent-context/context-inventory/`. Tools: `global/scripts/context-inventory-{build,batch,merge}.py`.

Each row is a lead from a reviewer. Re-read the file and confirm the claim before acting on it.
